# 基于迭代求解的房间冬季采暖负荷计算系统 —— 项目说明

## 1. 项目简介

本系统按题目 A4 的要求计算房间冬季采暖设计热负荷，并回答"给定散热器能力，房间最终能稳定在几度"的问题。程序从 `envelope.txt` 读入各围护面的朝向、面积与传热系数，从 `weather.txt` 读入室外计算温度、朝向修正系数、缝隙渗风参数与散热器供热能力；先按朝向修正传热系数，再逐面累加围护结构传热热损失，按缝隙法估算冷风渗透热损失，汇总得到设计工况总负荷与单位面积指标。

在平衡工况下，系统用不动点迭代求解方程 `Qsup = (S + C)·(tn − tw)`（S 为围护总传热能力、C 为渗透总系数），得到仅靠散热器供热时房间能达到的热平衡温度；随后对室温 14\~24 ℃ 与供热能力 2000\~4000 W 做批量敏感性实验，最终把全部结果写入 `heat_load_report.txt`（7 节报表）。

## 3. 程序结构与文件说明

工程为多文件结构：10 个 `.c` + 10 个 `.h`，模块编号与题目 M1~M10 一一对应。

| 文件 | 模块 | 作用 |
|---|---|---|
| `main.c` | M10 | 主控菜单：do-while + switch 调度各模块，维护"已读入 / 已修正"状态，处理非法输入与 EOF |
| `EnvelopeIO.c/.h` | M1 | 围护结构参数文件读入：逐行解析并校验面积、K、朝向，非法行置 `valid=0` 并告警 |
| `WeatherIO.c/.h` | M2 | 室外气象参数读入：关键字-数值解析、缺项默认值、`tw` 符号纠正、区间校验与回显 |
| `KCorrect.c/.h` | M3 | 传热系数朝向修正：`kAdj = k × α`，输出"原始 K—alpha—修正 K"对照表 |
| `HeatLoss.c/.h` | M4 | 围护热损失逐面累加：`q = K′·A·(tn−tw)`，输出逐面表与占比 |
| `Infiltration.c/.h` | M5 | 冷风渗透：`Q_渗 = 0.28·c·ρ·L·(tn−tw)`，提供纯函数供 M6/M7/M8 复用 |
| `Equilibrium.c/.h` | M6 | 热平衡温度迭代：不动点迭代求 `g_tn`，含收敛判据、100 轮上限与 `C ≥ S` 时的发散兜底 |
| `SumLoad.c/.h` | M7 | 设计工况汇总：总负荷 `g_qTotal`、房间面积与单位面积指标，并与 50~80 W/m² 对照 |
| `Sensitivity.c/.h` | M8 | 敏感性实验：室温 6 档、供热能力 5 档两张表 |
| `Report.c/.h` | M9 | 报表输出：把参数、逐面表、渗透、汇总、迭代与两张敏感性表写入 `heat_load_report.txt` |
| `common.h` | 公共 | 常量与校验区间、`struct Envelope` / `struct Weather`、全局变量声明、BOM/字符串/对齐等小工具 |
| `run.bat` / `run.sh` | 工具 | 一键编译并运行（Windows / Linux、macOS），脚本会 `cd` 到自身目录并在缺少输入数据时自动复制标准数据 |
| `README.md` | 文档 | 本文件 |

## 5. 输入数据

### 5.1 读取约定

- 程序**固定读取当前工作目录**下的 `envelope.txt` 与 `weather.txt`（文件名硬编码，不支持命令行参数）。
- 切换数据集 = 把某个数据集目录里的这两个文件**拷贝覆盖**到程序所在目录，或直接在数据目录中运行 `app.exe`（如 `..\..\03-Code\app.exe`）。
- 两个文件都按 UTF-8 保存；带不带 BOM 均可（程序会自动跳过 BOM）。

### 5.2 随包数据集（`04-Data/`）

| 数据集 | 场景 | 关键结果（设计室温 18 ℃） |
|---|---|---|
| `01_clean` | 标准数据、无异常 | 7 面有效、0 警告；总负荷 1862.01 W，指标 103.45 W/m²，平衡室温 32.66 ℃（5 轮） |
| `02_anomaly` | 注入 126.0 面积、X 朝向、`tw` 丢负号 | 有效 5 / 警告 2；`tw` 自动纠正为 −19.0 ℃；总负荷 1481.39 W，平衡 45.94 ℃ |
| `03_harbin` | 哈尔滨严寒工况 `tw = −24.2 ℃` | 总负荷 2182.23 W，指标 121.24 W/m²，平衡 33.81 ℃ |
| `04_midroom` | 4 m × 5 m × 3 m 中等房间、8 个围护面 | 8 面有效；总负荷 1819.92 W，指标 91.00 W/m²，平衡 48.46 ℃ |
| `05_bad_format` | 非法行压力测试（无逗号、越界、小写朝向等） | 有效 2 / 警告 8；`tw = 0` 单独提示；总负荷 285.63 W，平衡 163.85 ℃（13 轮） |
| `06_boundary` | 面积/K/缝隙长/供热能力取边界值 | 面积 1.0 与 50.0、K 0.2 与 3.5 均判有效；总负荷 6277.79 W，平衡 −13.11 ℃（供热不足） |
| `07_all_invalid` | 全部围护面非法 | 有效 0；M6 提示"围护总传热能力 S = 0"，M7 提示指标无法计算，程序不崩溃 |

### 5.3 `envelope.txt` 格式

一行一个围护面，逗号分隔；**首行可以是表头，也可以直接是数据**（解析不出 4 段就按表头跳过）。

```
名称,朝向代码,面积m2,传热系数W/(m2K)
北外墙,N,12.6,0.45
南外墙,S,12.6,0.45
北外窗,N,4.2,2.30
屋面,R,18.0,0.35
地面,U,18.0,0.30
```

| 字段 | 说明 | 校验（非法行置 `valid=0` 并告警） |
|---|---|---|
| 名称 | 面名称，UTF-8 下建议 ≤5 个汉字 | 超 15 字节会截断并告警 |
| 朝向代码 | `N`/`S`/`E`/`W`/`R`（屋面）/`U`（地面） | 必须是大写且在上述集合内，`R`/`U` 不做朝向修正 |
| 面积 | 单位 m² | 1 ~ 50 |
| 传热系数 | 单位 W/(m²·K) | 0.2 ~ 3.5 |

> 最多读 20 个围护面，超出部分忽略并告警；空行自动跳过。

### 5.4 `weather.txt` 格式

一行一条，格式为「关键字,数值」，按关键字**子串匹配**，顺序不限。

| 关键字（示例写法） | 含义 | 单位 | 缺项时的默认值 |
|---|---|---|---|
| `采暖室外计算温度tw_C` | 室外计算温度，必须 < 0 | ℃ | −19.0 |
| `北向朝向修正` | 北向 α | — | 1.10 |
| `东西向朝向修正` | 东/西向 α | — | 1.00 |
| `南向朝向修正` | 南向 α | — | 0.85 |
| `每米缝隙渗风量L_m3hm` | 每米缝隙渗风量 L | m³/(m·h) | 0.90 |
| `北窗缝隙总长m` | 北窗缝隙总长 | m | 7.2 |
| `南窗缝隙总长m` | 南窗缝隙总长 | m | 7.2 |
| `散热器供热能力Qsup_W` | 散热器供热能力 | W | 2600 |

> 校验规则：`tw` 为正视为丢负号、自动取负并告警；`tw = 0` 单独告警；L、缝隙长、Qsup、α 越界只告警、不擅自改值；缺项按上表默认值处理并逐条告警；未知关键字告警后忽略。

## 8. 已知问题与限制

1. **输入文件名硬编码**为 `envelope.txt` / `weather.txt`，不支持命令行参数，切换数据集需手工拷贝（`run.bat` / `run.sh` 只自动处理标准数据这一种情况）。
2. **无图形界面**，敏感性实验只能看屏幕/报表里的表格，没有曲线图；室温与供热能力的趋势需要自己从表中读数。
3. 只实现了题目必做部分：**未实现**高度附加、风力附加、夜间值班工况（12 ℃）与多房间汇总排序；房间面积按地面面积近似，异形房间会失真。
4. 平衡室温可能远高于 18 ℃（如 `01_clean` 的 32.66 ℃），这是题设定值 `Qsup` 模型的必然结果，不是算错；实际工程中散热器出力会随室温升高而下降，本系统未计该特性。
